# 교훈

> 최종 수정: 2026-11-04 · 시안과 mod 를 만들며 겪은 실수와 다음에 쓸 방법

## 매 틱 전체 다시 그리기는 무겁다
- 시안 1차가 0.1초마다 화면 전체(글자마다 span)를 다시 그려 메인 스레드 66%를 썼다. 바뀐 줄만 다시 그리고 안 보이는 것은 멈추니 8% 미만.
- mod 에서도 같다: 타이머로 다시 그릴 때 바뀐 값만 atom 에 쓰고, 보이지 않는 패널은 갱신하지 않는다.

## 고친 뒤 숫자가 너무 좋으면 먼저 의심한다
- 고친 줄이 실제로 반영되지 않아 그리기가 매번 오류로 멈췄는데, CPU 숫자만 보고 좋아졌다고 착각할 뻔했다. 화면 안에서 직접 계측(오류·갱신 줄 수)해 원인을 찾았다.

## 헤드리스 스크린샷
- `--virtual-time-budget` 로 찍으면 IntersectionObserver·타이머가 실제처럼 돌지 않아 빈 화면이 나온다. DevTools 프로토콜로 실제 시간을 기다린 뒤 `Page.captureScreenshot` 으로 찍는다.
- 크롬 `--screenshot=` 경로에 한글이 있으면 파일이 안 생긴다. 영문 임시 폴더에 찍고 복사한다.

## 실제 화면은 오르카 터미널에서 읽는다
- 시험(`claude plugin test`)은 요소 목록만 주고 칸 배치는 계산하지 않아, 겹침·줄바꿈·잘림은 못 잡는다.
- 이 세션이 오르카 터미널에서 돌면 `orca terminal read --terminal <handle> --screen --json` 으로 그려진 화면을 글자로 읽을 수 있다. 고친 뒤 「됐다」 하기 전에 이걸로 본다(겹친 ▶, 잘린 탭 버튼, 예전 캐릭터 그림을 이렇게 찾았다).

## 세션에 남는 값은 「더하기」만 하면 낡는다
- 캐릭터 목록 atom 에 매번 더하기만 해서, 뺀 캐릭터가 남고 리뉴얼한 그림이 화면에 안 나왔다(사용자: 「적용이 하나도 안 된 상태」).
- 코어가 가진 목록은 세션 시작·다시 불러오기 때 새로 채우고, 다른 팩은 `hud.ready` 를 듣고 다시 보내게 한다.

## 픽셀 색이 화면에서 달라 보이면 찍어서 잰다
- 곰이 하늘색: 땀방울 픽셀 글자 `B` 가 곰·토끼 몸 색 글자와 겹쳤다. 특수 표시에는 색 글자로 안 쓰는 기호(`~`)를 쓴다.
- 호빵이 분홍: 터미널이 색을 채널마다 16단계(0x11 배수)로 줄여 그려, 크림색 `#fbf3e8` 이 `#ffeeee` 가 됐다. 흰색·크림색처럼 옅은 색은 그 단계 위의 색(`#ffeedd`, `#eeeeee`)으로 고른다.
- 글자 읽기(`orca terminal read`)로는 색을 못 본다. `orca terminal switch` 로 이 세션을 앞에 띄우고 `orca computer get-app-state` 스크린샷의 픽셀을 재고, 사용자가 보던 터미널로 되돌린다.

## 탭은 한 번 열어 두면 끝이 아니다
- 「HUD 설정」 탭이 또 사라졌다(사용자: 「늘 보이게 하라고 했는데 또 안 보이네」). 세션 시작 때 한 번만 열어서, 다시 불러오기·그리기 오류로 엔진이 탭을 내리면(`ui.close` 의 `origin.kind === 'unload'`) 되살아나지 않았다.
- 지금은 `ensurePanes` 가 세션 시작·답변 끝마다 `$.ui.panes()` 로 확인해 빠진 탭을 다시 연다. 사람이 닫는 것은 `ui.close` 훅에서 `next` 없이 답해 막는다(「닫기」로 닫으면 다시 안 떠서 사용자가 막으라고 함). 못 열면 까닭을 디버그 기록에 남긴다.
- 화면 조작(orca computer 클릭·키 입력)은 사용자 마우스·키보드를 실제로 쓴다. 허락 없이 쓰지 않는다. 글자 키는 패널이 아니라 입력창으로 들어갈 수 있다.

## 셸에서 문서를 쓸 때
- 큰따옴표·heredoc 안의 백틱은 명령 치환이 되어 파일이 망가진다(이 문서가 한 번 자기 자신으로 덮였다). 문서는 Write 도구로 쓰거나 `<<'EOF'` 로 쓴다.

## mod 엔진 규칙(검증기·시험에서 걸린 것)
- atom 은 **쓰는 파일 안에** 선언돼 있어야 검증기가 따라간다. 다른 파일에서 import 한 atom 으로 `update` 하면 거절된다 → 파일마다 같은 plugin·key·shape 로 다시 선언한다.
- `$` 를 다른 파일의 함수에 넘길 때 그 함수는 `function` 선언이어야 한다(화살표 함수 const 는 거절).
- `claude plugin test` 의 `$` 에는 다른 플러그인이 더한 명사(`$.hud`)도, `$.state` 도 없다. 상태는 `on('state.get')` 으로 시험이 대신 답한다(`{ value: { value: { shape, value }, version } }`). 시계는 `mock.clock(on)`. 시험의 `on` 은 `$` 를 처음 부르기 전에 모두 걸어야 한다.
- 모바일 화면 표에도 `Select`·`Input` 이 들어 있지만 그려지지 않는다. 화면 종류(`e.surface`)로 판단해 버튼 줄로 대신한다.
- `$.clock.every`·`$.clock.after` 모두 `cancel()` 이 있는 값을 돌려준다.
- 패널은 한 번에 하나만 보이고 나머지는 탭이 된다. 두 패널을 나란히 띄울 수 없다.
- 시험 결과를 `grep ... && git commit` 으로 이으면 실패해도 커밋된다(grep 은 「fail」 줄을 찾아도 성공). 시험 확인과 커밋은 따로 한다.

## 사용 영상·사진 찍기(README)
- 마우스로 HUD를 누르다가, 화면 위에 늘 떠 있는 다른 앱 창(메신저)을 눌러 광고 탭이 수십 개 열리고 프로필 창이 떴다. 누르기 전에 그 자리를 덮은 창이 없는지 화면 전체를 찍어 확인한다. HUD 조작은 마우스 대신 `orca terminal send` 로 키를 보낸다(`Ctrl+X` `Tab` 으로 패널에 초점, `Tab`/`Shift+Tab` 이동, `Enter` 누르기, `Esc` 나가기). 패널 초점 없이 보낸 글자는 입력창으로 가고, `Tab` 은 입력창 제안을 받아들인다.
- 「미리보기 버튼이 안 눌린다」고 판단한 것도 그 창 때문이었다. 엔진 디버그 기록(`claude --debug-file`)에 `ui.press` 줄이 안 찍히면 코드보다 눌린 자리부터 의심한다.
- 녹화는 `PrintWindow`(창 내용만, 가려져도 찍힘)로 초당 8~12장을 파일로 바로 저장한다. 찍히는 것은 오르카에서 지금 보이는 탭뿐이라, 녹화하는 동안 사용자에게 탭을 그대로 두라고 먼저 말한다.
- 패널 너비는 사람이 정한 값(`~/.claude.json` 의 `pluginPanes.dockColumns`, 최소 24)이 이긴다. 넓혀 찍을 때는 이 값을 바꾸고 새 세션을 띄운 뒤, 끝나면 되돌린다. 키로는 패널 초점에서 `Ctrl+X ←`/`→`.
- Git Bash 에서 `/exit` 처럼 `/` 로 시작하는 글자를 보내면 경로로 바뀐다. `MSYS_NO_PATHCONV=1` 을 붙인다.
- 데모는 저장소 밖 짧은 경로의 빈 폴더에서 새 세션으로 찍는다(머리글에 경로가 보임). 사용자 전역 규칙이 데모 세션에도 걸리니, 요청에 「체크리스트 파일은 만들지 마」처럼 적고, 실행할 명령만 그 폴더 `.claude/settings.local.json` 에서 허용한다.
- 편집은 프레임을 PNG로 남겨 한 장씩 본다. 걸러 낸 것: 터미널이 다시 그리는 순간의 빈 프레임, 오르카가 패널 위에 띄운 둥근 버튼(아래 줄 색으로 덮음). 캐릭터 깜빡임·눌림은 정상 동작이라 남긴다. GIF는 시간 단위가 1/100초라 프레임 길이를 60ms처럼 10ms 배수로 맞추고, 팔레트는 여러 프레임에서 모아 만든다(드문 색이 빠지면 화면이 통째로 같은 프레임으로 합쳐진다).
