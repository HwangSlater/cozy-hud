# 교훈

> 최종 수정: 2026-11-03 · 시안과 mod 를 만들며 겪은 실수와 다음에 쓸 방법

## 매 틱 전체 다시 그리기는 무겁다
- 시안 1차가 0.1초마다 화면 전체(글자마다 span)를 다시 그려 메인 스레드 66%를 썼다. 바뀐 줄만 다시 그리고 안 보이는 것은 멈추니 8% 미만.
- mod 에서도 같다: 타이머로 다시 그릴 때 바뀐 값만 atom 에 쓰고, 보이지 않는 패널은 갱신하지 않는다.

## 고친 뒤 숫자가 너무 좋으면 먼저 의심한다
- 고친 줄이 실제로 반영되지 않아 그리기가 매번 오류로 멈췄는데, CPU 숫자만 보고 좋아졌다고 착각할 뻔했다. 화면 안에서 직접 계측(오류·갱신 줄 수)해 원인을 찾았다.

## 헤드리스 스크린샷
- `--virtual-time-budget` 로 찍으면 IntersectionObserver·타이머가 실제처럼 돌지 않아 빈 화면이 나온다. DevTools 프로토콜로 실제 시간을 기다린 뒤 `Page.captureScreenshot` 으로 찍는다.
- 크롬 `--screenshot=` 경로에 한글이 있으면 파일이 안 생긴다. 영문 임시 폴더에 찍고 복사한다.

## 실제 화면은 오르카 터미널에서 읽는다
- 시험(`claude plugin test`)은 요소 목록만 주고 칸 배치는 계산하지 않아, 겹침·줄바꿈·잘림은 못 잡는다.
- 이 세션이 오르카 터미널에서 돌면 `orca terminal read --terminal <handle> --screen --json` 으로 그려진 화면을 글자로 읽을 수 있다. 고친 뒤 「됐다」 하기 전에 이걸로 본다(겹친 ▶, 잘린 탭 버튼, 예전 캐릭터 그림을 이렇게 찾았다).

## 세션에 남는 값은 「더하기」만 하면 낡는다
- 캐릭터 목록 atom 에 매번 더하기만 해서, 뺀 캐릭터가 남고 리뉴얼한 그림이 화면에 안 나왔다(사용자: 「적용이 하나도 안 된 상태」).
- 코어가 가진 목록은 세션 시작·다시 불러오기 때 새로 채우고, 다른 팩은 `hud.ready` 를 듣고 다시 보내게 한다.

## 셸에서 문서를 쓸 때
- 큰따옴표·heredoc 안의 백틱은 명령 치환이 되어 파일이 망가진다(이 문서가 한 번 자기 자신으로 덮였다). 문서는 Write 도구로 쓰거나 `<<'EOF'` 로 쓴다.

## mod 엔진 규칙(검증기·시험에서 걸린 것)
- atom 은 **쓰는 파일 안에** 선언돼 있어야 검증기가 따라간다. 다른 파일에서 import 한 atom 으로 `update` 하면 거절된다 → 파일마다 같은 plugin·key·shape 로 다시 선언한다.
- `$` 를 다른 파일의 함수에 넘길 때 그 함수는 `function` 선언이어야 한다(화살표 함수 const 는 거절).
- `claude plugin test` 의 `$` 에는 다른 플러그인이 더한 명사(`$.hud`)도, `$.state` 도 없다. 상태는 `on('state.get')` 으로 시험이 대신 답한다(`{ value: { value: { shape, value }, version } }`). 시계는 `mock.clock(on)`. 시험의 `on` 은 `$` 를 처음 부르기 전에 모두 걸어야 한다.
- 모바일 화면 표에도 `Select`·`Input` 이 들어 있지만 그려지지 않는다. 화면 종류(`e.surface`)로 판단해 버튼 줄로 대신한다.
- `$.clock.every`·`$.clock.after` 모두 `cancel()` 이 있는 값을 돌려준다.
- 패널은 한 번에 하나만 보이고 나머지는 탭이 된다. 두 패널을 나란히 띄울 수 없다.
- 시험 결과를 `grep ... && git commit` 으로 이으면 실패해도 커밋된다(grep 은 「fail」 줄을 찾아도 성공). 시험 확인과 커밋은 따로 한다.
